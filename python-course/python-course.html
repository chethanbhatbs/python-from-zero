What is programming?

What a program is, what code is, and why the computer needs every step spelled out.

A program is a list of exact steps

A program is a list of instructions that a computer follows, one after another. Every app you use is a program: WhatsApp, a calculator, a game, a website. Someone wrote each step.

You already know something that works this way: a recipe.

In a recipeIn a programMeaning
the stepsthe codethe instructions, written down
the cookthe computerthe thing that follows the steps
the ingredientsthe inputwhat goes in (a number you type, a file)
the dishthe outputwhat comes out (text on screen, a saved file)
cookingrunning (or executing)actually following the steps

Computers are fast, but they never guess

A person told "make tea" fills in the gaps: they boil water, find a cup, add sugar the way you like it. A computer cannot fill in gaps. It does exactly what is written, in the order it is written, and nothing else.

So programming is mostly this: breaking a job into steps small and exact enough that something with no common sense can still do it.

If one step is wrong, the computer still follows it. It will happily add the sugar before the water exists. A mistake in a program is called a bug, and finding and fixing it is called debugging.

Why we need a programming language

Inside, a computer only understands machine code: long runs of 0s and 1s. Writing that by hand is slow and almost impossible to read.

A programming language lets you write steps in something close to English, like print("Hi"). A translator program then turns it into instructions the machine can carry out. For Python, that translator is Python itself.

Syntax: the grammar of a language

Every language has grammar rules. In English, "the dog ran" is fine and "ran dog the" is wrong, but a person still understands it.

A programming language's grammar is called its syntax. The difference: the computer does not understand broken grammar at all. One missing bracket and Python refuses to run the whole file. That is why this course shows, for every rule, what breaks it.

WordPlain meaning

debuggingfinding and fixing bugs

Key takeaways

  • A program is a list of exact steps. The computer runs them in order, top to bottom, and never guesses what you meant.
  • Computers only understand machine code (0s and 1s). A programming language is readable text that gets translated for the machine.
  • Syntax is the grammar of a language. Break it, and the program does not run.
  • A mistake in code is a bug. Finding and fixing it is debugging.

Chapter 1

What is Python?

Who made it, where the name comes from, and why so many people learn it first.

Python in one line

Python is a programming language: a set of words and grammar rules for writing programs, plus the program (also called Python) that reads and runs them.

The official Python FAQ calls it "an interpreted, interactive, object-oriented programming language" and "a high-level general-purpose programming language". Four of those words, in plain English:

Interpreted
Run your file directly with python3 file.py. No app to build first.
Interactive
Type one line and see the result straight away (Chapter 2).
High-level
You write print("Hi"), not 0s and 1s.
General-purpose
Not made for one job: websites, data, automation, testing, AI.

Every language has to turn your code into machine code. They differ in when that happens and what you end up with.

Think of a speech. Compiling is translating the whole speech on paper first and handing over the printed copy. Interpreting is a live interpreter translating as you speak, every time you give it.

Python's hidden step: bytecode

The Python glossary says the line is "blurry": Python first compiles your code into bytecode, automatically and invisibly, then runs that. "The bytecode is also cached in .pyc files so that executing the same file is faster the second time." You never run a build step yourself, which is why Python still counts as interpreted. You can see the cache appear when one file imports another:

import os
import greet
print(os.listdir("__pycache__"))
Output
hello from greet
['greet.cpython-314.pyc']

The folder held greet.py. Importing it ran it, then Python saved its bytecode in a __pycache__ folder. Source: Python glossary: bytecode.

Who made it

Guido van Rossum, a Dutch programmer, created Python. He was working at CWI, a research institute in the Netherlands.

In his own words in the Python FAQ: "During the 1989 Christmas holidays, I had a lot of time on my hand, so I decided to give it a try." He shared it publicly in February 1991. It was built as a successor to an older teaching language called ABC, which he had worked on.

Today Python is owned by the Python Software Foundation (PSF), a non-profit formed in 2001, and built by volunteers all over the world. It is free.

Why it is called Python

Not after the snake. From the FAQ: Guido "was also reading the published scripts from 'Monty Python's Flying Circus', a BBC comedy series from the 1970s", and wanted "a name that was short, unique, and slightly mysterious".

The snake came later, as a logo idea. The blue and yellow in this page are the colours of that logo.

Compare: the same program in Java

A program that prints Hello. In Java you need a class and a method before you can print anything:

public class Main {
    public static void main(String[] args) {
        System.out.println("Hello");
    }
}

Output
Hello

Python 2 and Python 3

Python 3.0 came out on 3 December 2008 and changed some rules, so old Python 2 code does not always run on it. Python 2 was officially retired on 1 January 2020. Always learn and use Python 3. Old tutorials that write print "hi" without brackets are Python 2 (Chapter 3 shows the error you get).

This page was built with Python 3.14.7. Error messages can be worded slightly differently on older versions; the error type stays the same.

Where Python is weaker

No language is best at everything. Python is slower than languages like C for heavy number crunching (big libraries solve this by doing the heavy part in C for you), and it is not the usual choice for phone apps. Its spacing rules are strict (Chapter 2). None of this matters while learning.

Key takeaways

  • Python was created by Guido van Rossum, started over Christmas 1989 and shared in February 1991. It is named after Monty Python, not the snake.

Step 1: check Python is installed

Open the Terminal (on a Mac: press Cmd + Space, type Terminal, press Enter). The terminal is a window where you type commands instead of clicking. Type this and press Enter:

python3 --version

If it prints something like Python 3.14.7, you are ready. On Windows the command is usually python or py.

Way 1: the interactive prompt (try one line)

Type python3 on its own and press Enter. You get a >>> prompt. Each line you type runs immediately:

>>> 2 + 3
5
>>> print("Hi")
Hi
>>> exit()

Good for testing one line. Everything is lost when you close it. Type exit() to leave and get back to the terminal.

Way 2: a file (how real programs run)

Make a file called hello.py (any text editor works; VS Code is a common free one). The name must end in .py. Put this in it:

print("Hello")
print("I am learning Python")

In the terminal, go to the folder with the file and run it:

python3 hello.py

Python runs the lines from top to bottom and prints both. Use a file for every exercise on this page.

Rule 1The >>> prompt runs Python, not terminal commands

At >>> you are inside Python. Terminal commands like ls or cd mean nothing there. And python3 hello.py is a terminal command, so it does not work at >>> either.

✗ Breaks
ls
Error
Traceback (most recent call last):
  File "lesson.py", line 1, in <module>
    ls
NameError: name 'ls' is not defined

Why: Python sees ls as the name of something you never created. If you see >>>, type exit() first, then run terminal commands.

How Python reads your file: two passes

This one idea explains most errors you will see.

Rule 1Broken grammar stops the whole file, even the lines before it

Before running anything, Python checks the grammar of the entire file. If any line is broken, nothing runs.

✓ Works
print("line 1")
print("line 2")
Output
line 1
line 2
✗ Breaks
print("line 1")
print("line 2"
Error
  File "lesson.py", line 2
    print("line 2"
         ^
SyntaxError: '(' was never closed

Why: Line 2 is missing its closing bracket. Python found that in pass 1, so even line 1 never ran. Notice the error does not say line 1 was printed: it was not.

Rule 2Other errors stop at the line, and the lines above already ran

If the grammar is fine, Python runs line by line. When a line fails, Python stops there. Lines above it have already done their work.

✗ Breaks
print("line 1")
print(score)
print("line 3")
Error
line 1
Traceback (most recent call last):
  File "lesson.py", line 2, in <module>
    print(score)
          ^^^^^
NameError: name 'score' is not defined

Why: Pass 1 was fine (the grammar is correct). In pass 2, line 1 printed, then line 2 failed because score was never created. Line 3 never ran.

How to read an error message

An error message is called a traceback. It looks scary but has only three parts. Always read it bottom up.

Error typeFound inPlain meaningChapter
SyntaxErrorpass 1grammar is broken: a bracket or quote missing, a word in the wrong placeeverywhere
IndentationErrorpass 1spaces at the start of a line where they do not belong2
NameErrorpass 2a name that does not exist: a typo, wrong capital letter, or used too early4
TypeErrorpass 2the wrong kind of value for that action, like text + number4
ValueErrorpass 2the right kind of value with bad content, like int("abc")4
IndexErrorpass 2a position that does not exist in a string or list5, 6
KeyErrorpass 2a key that does not exist in a dictionary7
ZeroDivisionErrorpass 2dividing by 04
ModuleNotFoundErrorpass 2import of a module that does not exist or is not installed3

Rule 1Spaces at the start of a line matter

In Python, spaces at the start of a line (called indentation) have meaning. They are used to group lines, which you will meet later with if and loops. Until then, every line starts at the left edge.

✓ Works
x = 5
y = 6
print(x + y)
Output
11
✗ Breaks
x = 5
  y = 6
print(x + y)
Error
  File "lesson.py", line 2
    y = 6
IndentationError: unexpected indent

Why: The two spaces before y tell Python a group is starting, but nothing above opened one. Spaces inside a line are free: x=5 and x = 5 mean the same.

Rule 2One instruction per line

Each line holds one instruction. Two values side by side with nothing joining them is broken grammar.

✓ Works
x = 5
y = 6
Output
(nothing is printed)
✗ Breaks
x = 5 6
Error
  File "lesson.py", line 1
    x = 5 6
          ^
SyntaxError: invalid syntax

Why: Python cannot tell what 5 6 should mean. It even guesses: perhaps you forgot a comma.

Key takeaways

  • The >>> prompt runs Python. Terminal commands like ls or clear do not work there; type exit() to leave.
  • A SyntaxError stops the whole file before anything runs, even the lines above it.
  • Any other error stops at its own line. The lines above it have already run.
  • Read an error from the bottom up: error type and reason, then the line number and the ^ marks.
  • Spaces at the start of a line matter, and each line holds one instruction.

Rule 1print needs brackets

print() shows something on the screen. Whatever you put inside the brackets is what it shows.

print("hi") shows hi. The brackets are how you hand it the thing to show, so they are never optional.

✓ Works
print("Hello")
Output
Hello
✗ Breaks
print "Hello"
Error
  File "lesson.py", line 1
    print "Hello"
    ^^^^^^^^^^^^^
SyntaxError: Missing parentheses in call to 'print'. Did you mean print(...)?

Why: Without brackets it is Python 2 grammar. Python 3 even tells you: Did you mean print(...)?

Rule 2Text goes inside quotes; without quotes it is a name

Quotes tell Python "this is text, print it as it is". Without quotes, Python thinks the word is the name of something you stored.

✓ Works
print("Hello")
print('Hello')
Output
Hello
Hello
✗ Breaks
print(Hello)
Error
Traceback (most recent call last):
  File "lesson.py", line 1, in <module>
    print(Hello)
          ^^^^^
NameError: name 'Hello' is not defined

Why: Hello without quotes is a name, and you never created anything called Hello. Single or double quotes both work; they must match.

Rule 3Only text needs quotes

Numbers, True, False, None and names you already created are written without quotes. Quotes are only for text.

✓ Works

print(True)

print(city)

    city = Goa
           ^^^
NameError: name 'Goa' is not defined

Why: Without quotes, Goa is read as a name, and no name Goa exists. Quotes turn it into the text "Goa".

Anything after # on a line is a comment. Python skips it. Use comments to explain why a line exists.

Rule 1Everything after # is ignored, to the end of that line

A comment can take a whole line or sit at the end of a line of code.

A variable is a name you give to a value so you can use it later. You create one with =.

Rule 1= means "store", and the name goes on the left

= is not "equals" like in maths. It means: work out the right side, then put that name on the result.

✓ Works
age = 30
age = age + 1
print(age)
Output
31
✗ Breaks
30 = age
Error
  File "lesson.py", line 1

    ^^
SyntaxError: cannot assign to literal here. Maybe you meant '==' instead of '='?

Why: You cannot store something inside the number 30. Only a name can go on the left. (==, two equals signs, is for comparing: rule 1 of "Comparing and combining".)

Python runs top to bottom, so a variable must be created on a line above the line that uses it.

✓ Works

Output
10
✗ Breaks
print(score)
score = 10
Error
Traceback (most recent call last):
  File "lesson.py", line 1, in <module>
    print(score)
          ^^^^^
NameError: name 'score' is not defined

Why: When line 1 runs, line 2 has not happened yet, so score does not exist.

Read or write: the one idea behind all of it

Every action on a value is either a read (look at it: x[0], len(x), x[1:3], in, print) or a write (change it: x[0] = ..., append, sort, del).

All three types allow reads, and no read ever changes anything. Only a list allows writes. A string and a tuple refuse them, so to "change" one you build a new one and move the name to it.

= does not copy a list

This is the trap that catches everyone once. It all happens in your computer's memory (RAM) while the program runs: the list is stored there once, and a name is just a way to reach it.

Think of a Google Doc. b = a is sending a friend the same link: when they type, you see it, because there is only one document. b = a.copy() is File, Make a copy: now there are two documents.
